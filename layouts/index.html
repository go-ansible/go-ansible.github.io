Ansible's engine,
without Python.

Ansible's engine is a Python program that needs a matching interpreter on the control node. go-ansible reimplements it as importable Go packages rather than wrapping the Python binary — the same wire formats, the same merge orders, the same rendering rules, compiled into one static executable. Pure Go, CGO_ENABLED=0. BSD-3-Clause.

What is honoured, not what parses

A keyword that parses and does nothing is the worst failure.

A missing feature stops a playbook. A silently ignored one lets it succeed while not doing what it says — so this table is read from playbook/engine.go and playbook/playbook.go directly, not from the shipped-package list. Several fields exist on the Play/Task structs and parse cleanly from YAML while the engine never reads them; those are the rows that say so.

How far the module library reaches

71 of 71 of ansible.builtin, module and directive alike.

modules/registry.go registers 566 module names, each running against a live go-remoteexec/transport connection. All 62 of ansible.builtin’s real modules are there, and its 9 non-module playbook-engine directives — add_host, group_by, import_playbook, import_role, import_tasks, include_role, include_tasks, include_vars, meta — are wired into the engine itself rather than registered as modules, which is why they appear in the matrix above and not in the registry count. Beyond builtin: all 14 of ansible.posix, and thirteen curated batches covering 490 of community.general’s 577.

What is not covered is worth saying as plainly: 87 community.general modules remain — an increasingly SaaS-only remainder — along with every cloud-provider collection (amazon.aws, azure, google.cloud and the rest), which needs real API client SDKs rather than shell composition over a connection, and is a different kind of work that has not been started. Where a module could not be done honestly it fails loud instead: synchronize is an always-failing stub, because real synchronize runs rsync from the controller straight at the target’s own SSH endpoint, which this port’s connection abstraction cannot expose from inside a module. Each repository card above opens to the full scope rationale for its own package.

What it stands on

The transport lives outside this org, on purpose.

SSH, local execution and become/sudo are in go-remoteexec/transport, a project-neutral package shared with go-puppet-bolt/bolt. modules, playbook and cli depend on it directly instead of each shipping a transport of its own — the connection layer is not an Ansible-shaped problem, and a package two ports share is held to a harder interface than one with a single caller.

Why go-ansible

Compatibility with the real thing, measured.

The bar is not a plausible reimplementation: it is agreeing with ansible-core on the same input. A differential corpus runs the same playbook through both and compares the transcripts byte for byte — and the divergences that remain are named rather than rounded off.

🔐

The vault format, byte for byte

AES-256-CTR with a PBKDF2-HMAC-SHA256 key and an encrypt-then-MAC tag, hex-wrapped at 80 columns — ansible.parsing.vault.VaultAES256's wire format, not a reinterpretation of it. Each side decrypts the other's files; a bad HMAC fails closed, in constant time, before the ciphertext is touched.

🧩

The rule naive ports miss

A value that is a single {{ "{{ expr }}" }} and nothing else renders to the expression's native type — a list, a dict, an int — not a string. And a null is not an undefined: default() does not fire on one, which is what Jinja2 does and what a port usually gets wrong.

📐

Precedence as a ladder

Role defaults up through play, role, block and task vars, registered vars, role params and --extra-vars, merged low to high. Which(key) answers the question a precedence bug actually raises: why did this value win?

🧪

Judged against the real binary

Every claim here was checked by running ansible-core beside this port and diffing the output — six of six transcripts byte-identical on the last sweep, with and without -v. The sweep is also what finds things: it turned up that every banner was missing the stars real pads it to 80 columns with, because the expectations in our own tests had been hand-written rather than captured. Where the two disagree and the cause is upstream — three cases inside the template engine, one needing a second account — the case stays in the corpus as a named witness rather than being deleted.

📦

566 modules, one contract

A function taking a target connection and rendered args, returning changed/failed/msg. All 62 real ansible.builtin modules, all 14 of ansible.posix, and fifteen curated community.general batches. Unlike Ansible, nothing is copied to the target: each module runs on the control node and reaches the host through Exec/Put/Fetch.

🚫

Honest stubs over quiet approximations

synchronize is an always-failing stub with its reason written down: the real one runs rsync from the controller straight at the target's own SSH endpoint, which this connection abstraction cannot expose from inside a module. A silent approximation would have been easier, and wrong.

Security

A value that reaches a command string reaches a shell.

That is the whole threat model, and it has two halves: a playbook value changing a command's structure, and a credential landing where ps can read it. The module library was audited against both. It found one of each — written down here rather than quietly patched, because a port that only publishes its clean audits has not published an audit.

⛔

A target’s data is not a template

A module’s result is data the managed host chose. This port re-rendered it as Jinja — and lookup('pipe', …) runs on the control node, so a host returning {{ "{{ lookup('pipe','touch FILE') }}" }} created that file where the vault password and the fleet’s SSH keys live. Real refuses by wrapping such data in AnsibleUnsafeText. Three routes, and the proof of concept kept firing until all three closed — including one call site added by a feature written hours earlier. A brake is only as good as its least-covered caller.

⛔

Quoting is the control, not care

Every interpolated value goes through shellQuote — 1 715 call sites across 608 files. Mechanical on purpose: being careful does not scale to that, and a missed site looks exactly like a deliberate one until somebody looks. What the audit found: async_status's jid, straight from a playbook argument, was interpolated unquoted — into an rm -rf. A jid of x; touch /tmp/pwned ; ran that touch.

🔭

The ps boundary, measured

An environment assignment written as a command prefix is not always visible, and which shape it is decides it. sh -c "VAR=x sleep 4" leaves nothing — the shell execs into the command. sh -c "VAR=x sleep 4; true" leaves the whole value, because a second statement means the shell must stay alive holding it. An earlier probe said the opposite; its canary was a fixed string the shell that had written the probe still carried.

🔑

Credentials go in the environment

Through transport's ExecWithEnv — what real Ansible does with run_command's environ_update. An optional interface, not a Connection method, because SSH genuinely cannot set arbitrary variables: sshd's AcceptEnv decides. What the audit found: of 24 modules building a CREDENTIAL= prefix, 23 were the safe lone-command shape and keyring was not — two statements, so the shell held both passwords for the command's whole life.

🧯

A fix that breaks parity is not a fix

The first jid validator returned an error for a malformed id. Real Ansible accepts jid: nope and reports could not find job, and an existing test caught the difference. A malformed jid is now mapped to exactly that answer: real's behaviour, and a value that never reaches a shell. The next person's workaround for a security fix that breaks their playbook is to turn it off.

🔍

A test that drove one state

The first keyring fix closed two of its three call sites and its regression test passed — it drove state: present, and state: absent is the only state that reaches the third. The detector that found the original exposure still named the file afterwards; that is what surfaced it. Each case now carries a witness: the command its own state must reach, so a case that returns early cannot pass by finding no secret in no commands.

⛔

The file we examined and the file we ran

An inventory path is stated and its mode decides it is a dynamic inventory script — then the same string went to exec.Command, which does a $PATH lookup for any name with no separator. So -i inv.sh validated ./inv.sh and executed a different inv.sh from $PATH. Measured with an impostor of the same basename: FROM-SOMEWHERE-ON-PATH before, the named file after, and real ansible-core runs the file it was pointed at. The audit question is not “is there a $PATH lookup?” — ansible-vault’s $EDITOR is right to do one — but “did something already decide this string names one file?”

♾️

One typo, a goroutine per host per task

gonja’s lexer runs in a goroutine on an unbuffered channel, so an expression that fails to parse mid-stream left it blocked on a send nobody would ever receive. when: is evaluated once per task, per host: +200 goroutines for 200 evaluations, held with their input, for the length of the run. The first probe reported zero — its bad expression failed at the end of the stream, where nothing is left unsent. A test case has to fail in the right place. Lexing synchronously fixed it and made that path 2.05× faster.

📍

What remains, named

On macOS keyring runs security add-generic-password … -w "$USER_PASSWORD", and that value is in one short-lived process's argv while it runs. There is no stdin form — measured — and the Keychain API needs cgo, which this port does not use. Linux does not have it: secret-tool reads stdin. Two vendor CLIs, rollbar-cli and ma-shell, have the same irreducible flag, confirmed by reading their source.

Every detector behind those numbers was shown able to report a violation before its zero was believed — the credential-prefix check was handed the pre-fix keyring line and fired on it. Full writeup: the Security page.
