go-ansible

A pure-Go, functional-parity port of Ansible — Vault-compatible encryption (vault), inventory parsing (inventory), Ansible's variable precedence ladder (vars), and Jinja2-compatible templating (template), with no Python, no C extensions, and one static binary.

CGO_ENABLED=0 byte-compatible with ansible-vault Jinja2-compatible templating order-faithful precedence ladder amd64 · arm64 · riscv64 · loong64 · ppc64le · s390x BSD-3-Clause
Documentation GitHub

Ansible's own engine is a Python program that shells out to modules and needs a matching interpreter on the control node. go-ansible reimplements that engine as importable Go packages instead of wrapping the Python binary — the same wire formats, merge orders, and rendering rules, compiled into a single static executable with no interpreter to install and no C toolchain to cross-compile against.

The bar for every component here is compatibility with the real thing, not a plausible reimplementation of it: vault reproduces ansible.parsing.vault.VaultAES256's exact byte format, and template implements the native-type rendering rule that trips up naive Jinja2 ports. Four components are shipped and tested today; module execution, the playbook/role engine, fact gathering, a Galaxy client, and the ansible-* CLI binaries are tracked on the roadmap and are not yet functional — they are not listed below until they are.

More on the way

Module execution, the playbook/role/task engine, fact gathering, a Galaxy client, and the ansible-* CLI binaries live in their own repositories under github.com/go-ansible but don't have working code yet, so they aren't listed as repositories above — see the roadmap for what's next. The playbook engine is the piece that will drive vars and template together against a real play, rather than each being exercised standalone as they are today.
